# 프로젝트 및 컴포넌트 가이드라인

이 프로젝트를 수정하기 전에 이 문서를 먼저 확인한다.
아래는 사용자가 정한 화면 구성과 콘텐츠 관리 기준이다. 이후 사용자의 명시적인 변경 요청이 있으면 그 요청을 우선한다.

## 실행 환경

- 실제 React + Vite 앱은 저장소 루트의 `github_page` 폴더에 있다.
- 처음 실행할 때 해당 폴더에서 `npm.cmd install` 후 `npm.cmd run dev`를 실행한다.
- 설치된 의존성 파일이 누락되면 실행 중인 서버와 설치를 종료하고 `npm.cmd ci`로 다시 설치한다. 설치 완료 후 개발 서버를 실행한다.
- PowerShell에서는 실행 정책 오류를 피하기 위해 `npm.cmd`를 사용할 수 있다.
- 개발 서버 주소는 터미널에 표시된 주소를 사용한다. 빌드는 `npm.cmd run build`이며 결과는 `dist`에 생성된다.

## 폴더 역할

- `src/App.jsx`: 앱 조합과 최상위 탭 상태.
- `src/components`: 재사용 UI와 페이지 섹션.
- `src/data`: 프로필, 카테고리, 게시글 등 정적 데이터.
- `src/assets`: 썸네일과 기타 이미지. 사용자가 제공한 스크린샷은 `src/assets/screenshot/n8n-study-1/`처럼 글 ID별 폴더에 보관한다.
- `src/hooks`: 공유 상태 로직. 기존 브라우저 저장 훅은 비활성 기능으로 보관한다.
- `src/styles`: 목적별 CSS. `app.css`는 import 진입점으로 유지한다.
- `src/utils`: React 훅이나 컴포넌트가 아닌 헬퍼.
- `docs`: 프로젝트 유지보수 규칙.

## 내비게이션과 메인 페이지

- 상위 메뉴는 ‘메인 페이지’와 ‘작성 글’로 구성한다. 별도의 ‘소개’ 메뉴는 사용하지 않는다.
- 소개 정보는 메인 페이지에 통합하고 이력서 형태로 표현한다.
- 메인은 이름·자기소개·GitHub·연락처, 기술 스택, 경력 및 활동, 프로젝트, 업무 강점으로 구성한다. 학력 및 교육 섹션은 표시하지 않는다.
- 경력과 프로젝트는 오래된 이력부터 최근 순서로 나열한다. 프로젝트에는 실무 게임 기획 경험과 웹 개발, 개인 사이트를 포함하고 학원 프로젝트는 제외한다.
- 프로필은 `src/data/resume.js`에서 관리한다.
- 실제로 제공되지 않은 경력·학력·연락처나 숙련도를 만들어 넣지 않는다. 미제공 정보는 ‘작성 예정’으로 표시한다.
- 메인에서 GitHub와 공부 기록으로 이동할 수 있게 한다.
- 페이지 탭은 페이지 제목 아래에서 전체 너비를 사용한다. 헤더 오른쪽 위로 옮기지 않는다.

## 게시글 저장과 작성 기능

- 현재는 데이터베이스 없는 정적 사이트다. 화면의 글 작성 기능은 주석 처리하고 작성·수정·삭제·내보내기 UI를 노출하지 않는다.
- 기존 작성 화면 코드는 `PostsPage.jsx`의 주석으로 보관한다. `PostEditor`, `RichTextEditor`, `useStoredPosts` 등도 복구 가능하도록 보관하되 현재 읽기 화면에 연결하지 않는다.
- 게시글은 `src/data/posts.js`의 정적 목록으로 관리한다. 긴 글은 `n8nStudy2.js`처럼 별도 데이터 파일로 분리해 목록에 포함할 수 있다.
- 브라우저 저장소나 내보내기 기능에 의존하지 않고 데이터 파일을 수정해 게시글을 추가한다.
- 로컬 콘텐츠 반영과 실제 원격 배포를 구분해 보고한다. 빌드 성공만으로 사이트에 배포됐다고 표현하지 않는다.
- 사용자가 배포를 명시적으로 요청하기 전까지 로컬 소스만 수정하고 빌드·검증한다. `build:pages`, 배포용 커밋과 원격 푸시는 자동으로 실행하지 않는다.

## 글 목록과 카테고리

- 넓은 화면에서는 왼쪽 카테고리, 오른쪽 썸네일 카드 목록으로 배치한다.
- 기본 카테고리는 ‘전체’, ‘AI’, ‘코딩’, ‘일상·기록’이다. 선택한 카테고리의 글만 표시하고 개수와 선택 상태를 보여준다.
- `topic`은 왼쪽 대분류, `category`는 카드의 세부 주제다. 예: `topic: 'AI'`, `category: 'N8N'`.
- `postCategories`에는 글이 없어도 표시할 분류를 둔다. 빈 분류에는 안내와 전체 글로 돌아가는 버튼을 제공한다.
- 카드는 PC에서 가로 2개, 600px 이하에서 1개로 표시한다. 카테고리는 820px 이하에서 상단으로 이동한다.
- 각 카드에는 썸네일, 주제, 날짜, 제목, 짧은 요약, 예상 읽기 시간을 넣는다.
- 카드 전체를 클릭하거나 키보드로 선택하면 상세 화면이 열린다.
- 상세 화면에서도 카테고리를 이동할 수 있고, 목록 복귀 시 선택한 카테고리를 유지한다.

## 상세 화면과 글 길이

상세 화면은 아래 여섯 항목과 바로가기 목차를 유지한다.

| 표시 항목 | 데이터 필드 | 작성 기준 |
| --- | --- | --- |
| 파이프라인 | `sections.pipeline` | 공부나 작업의 흐름을 짧은 단계로 표시 |
| 진행하면서의 문제점 | `sections.problems` | 핵심 문제와 확인할 사항 |
| 리프레이밍 | `sections.reframing` | 관점의 변화 |
| 솔루션 | `sections.solution` | 해결 방법 또는 다음 검증 계획 |
| 임팩트 | `sections.impact` | 확인된 결과 또는 기대 효과 |
| 리플렉션 | `sections.reflection` | 배운 점과 다음 시도 |

- 아래 다섯 항목은 각각 **1~2문장의 짧은 문단 하나**로 쓴다. 긴 배경 설명이나 반복되는 주의사항을 넣지 않는다.
- 사용자가 제작한 환경과 워크플로를 소개하는 공부 1~5는 `explanationOnly: true`로 목적과 구성 설명을 표시한다. 피드백·점검·개선안·검증 계획과 다섯 회고 항목은 포함하지 않는다.
- Discord Gemini Bot 글은 파이프라인·문제점·리프레이밍·솔루션·임팩트·리플렉션 UI와 목차를 표시한다. 추가로 제공받기 전까지 다섯 회고 항목은 빈 배열로 두고 기본 미작성 안내를 표시한다.
- 스크린샷을 대표 이미지로 사용할 때는 `thumbnailIsWorkflow: true`로 원본 비율을 유지한다. 본문 스크린샷은 원본 크기보다 확대하지 않는다.
- 자세한 개념, 노드 설명, 예시 요청 등은 파이프라인 아래의 **공부 메모**에 둔다.
- `studyNotes`의 `title`, `paragraphs`, `items`로 메모를 소제목·문단·목록으로 나눈다.
- 사용자가 요약을 요청한 아래 다섯 항목과 공부 메모를 구분한다. 별도 요청 없이 공부 메모나 원본 이미지를 함께 줄이지 않는다.
- 본문은 일반 텍스트 데이터로 표시한다. 기존 `content`와 `contentHtml`을 새 글의 본문 형식으로 사용하지 않는다.
- 실제 경험, 완료된 해결, 실행 성공, 수치 성과를 임의로 만들지 않는다. 분석·개선안·실습 계획·기대 효과는 그 성격이 드러나게 쓴다.
- 기술 설명을 보완할 때는 공식 문서를 확인하고 필요하면 `sources`에 참고 링크를 넣는다.

## 이미지 사용

- 사용자가 제공한 사진은 원본 그대로 사용한다. 원본을 사용할 수 있는데 유사한 이미지로 다시 만들지 않는다.
- 카드 썸네일과 본문 설명 이미지는 별도 용도로 관리한다.
- 썸네일을 나중에 제공한다고 한 경우 임시 썸네일을 사용할 수 있다. 이후 교체하기 쉽게 둔다.
- 워크플로 스크린샷은 파이프라인 설명과 단계 목록 사이처럼 분석을 이해하기 좋은 위치에 배치한다.
- 본문 이미지는 원본 비율을 유지하고 자르지 않는다. 클릭하면 새 탭에서 원본을 크게 볼 수 있게 한다.
- `workflowImage`, `workflowImageAlt`, `workflowImageCaption`으로 원본 경로·대체 텍스트·캡션을 관리한다.
- 여러 이미지를 함께 정리할 때는 해당 `studyNotes` 항목의 `image`, `imageAlt`, `imageCaption`으로 설명과 원본을 함께 배치한다.
- 설정 방법은 `steps`로 순서를 표시하고 `command`로 명령어를 굵게 표시한다. 명령어 뒤 설명은 `afterParagraphs`에 둔다.
- 파일은 assets에서 import하여 빌드에 포함한다. Windows 절대 경로나 로컬 파일 URL을 브라우저 이미지 경로로 쓰지 않는다.
- 채팅 이미지가 파일로 접근되지 않으면 그 한계를 설명하고 저장 경로를 요청한다. 사용자가 경로를 알려주면 파일을 찾아 확인한 뒤 연결한다.
- 현재 ‘N8N 공부 2’ 원본은 `src/assets/screenshot/n8n-study-2/캘린더.png`이다. 임시 썸네일과 별개로 본문에 표시한다.

## N8N 시리즈에 적용한 기준

- AI 카테고리에서 ‘N8N 공부 1’, ‘N8N 공부 2’처럼 제목을 일관되게 유지한다.
- 공부 1은 `n8nStudy1.js`에서 관리한다. Cloudflared → Docker 환경 → 소유자 계정 → 로그인 → Overview 순으로 환경을 설명하고 기존 자동화·API·HTTP·노드 메모를 유지한다. 마지막 메모에는 Exec의 계정 초기화 명령과 로컬 저장 데이터 유지 조건을 설명한다.
- 공부 2는 기존 캘린더 비서와 구글 시트·이메일 테스트를 앱 도구 선택이라는 주제로 통합한다. 기존 캘린더 메모와 이미지도 유지한다.
- 공부 3은 pushdata → 채팅 시 설정 → 파일 검색 및 저장 순서로 문서 적재·검색을 묶는다. 공부 4는 자막·타임스탬프 처리, 공부 5는 스토리메이커 자식 → 부모를 묶는다.
- N8N 글 목록은 공부 5 → 공부 4 → 공부 3 → 공부 2 → 공부 1 순서로 표시한다. 각 글 안의 이미지 순서는 유지한다.
- 스크린샷의 연결 구조와 내부 설정·실행 결과를 구분한다. 보이지 않는 설정이나 성공 여부는 단정하지 않는다.
- 공부 2의 Sheets 경고는 원인을 확정하지 않는다. 이메일 전송은 화면의 메모에만 있고 발송 노드는 보이지 않는다는 점을 구분한다.
- 두 글 모두 공부 메모는 상세히 유지하고 아래 다섯 항목은 짧게 유지한다.

## 컴포넌트와 CSS 규칙

- 반복되거나 독립적으로 커지는 UI는 역할이 드러나는 이름의 컴포넌트로 분리한다.
- 페이지 단위 컴포넌트에는 `Page` 접미사를 권장한다. 기존 `HeroSection`은 현재 메인 이력서를 표시한다.
- 표시 컴포넌트는 데이터를 props로 받고, 정적인 내용은 `src/data`에 둔다.
- `PostsPage`는 카테고리 선택과 목록·상세 전환을 담당한다.
- `PostList`, `PostCard`는 표시 역할에 집중하고 저장 로직을 갖지 않는다.
- CSS는 home, posts, navigation, responsive 등 목적에 맞는 파일에 둔다. `app.css`에 직접 몰아넣지 않는다.
- 비활성 편집기 스타일은 `editor.css`에 보관한다.
- 모바일에서도 텍스트와 이미지가 잘리지 않게 하고 키보드 포커스와 버튼의 접근성을 유지한다.

## 마무리 전 확인

- React 구조를 바꾼 뒤에는 `npm.cmd run build`를 실행한다.
- JSX나 스타일을 바꾼 뒤에는 `npm.cmd run lint`를 실행한다.
- 콘텐츠·이미지를 수정한 경우 빌드에서 데이터와 이미지가 정상 포함되는지 확인한다.
- 문서만 수정했다면 앱 테스트 대신 기존 규칙과의 충돌, 경로와 링크를 확인한다.
- 요청한 범위 외 기존 사용자 변경을 덮어쓰지 않는다.
